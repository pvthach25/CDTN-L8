# BT3 Test Plan - Smart CRM L8 (SE)

**Scope and exclusions.** The plan covers authentication, ticket state transitions, CSAT/NPS input rules, duplicate-survey prevention, survey ownership (OWASP A01), API health and clean Docker reproducibility. It deliberately excludes production deployment, load testing, accessibility certification and full penetration testing; those are outside the CDTN1 prototype scope.

**Test layers and quantities.** The repository contains **25 Node.js unit tests** (`npm test`), including four new owner-scope tests. The submission report contains **11 independently evidenced test scenarios**: TC01 unit regression; TC02 health; TC03 UI list/detail; TC04 and TC05 boundary values; TC06 invalid input; TC07 duplicate prevention; TC08 non-CLOSED ticket; TC09 missing authentication; TC10 Docker reproducibility; TC11 A01 cross-user ownership. TC02-TC11 are API/UI/integration/reproducibility scenarios and must be executed against an actual running Compose stack. The unit-test count and report scenario count must not be added together as if they were disjoint.

**Measurable success criteria.** (1) `docker compose exec app npm test` returns 25 PASS / 0 FAIL; (2) all 11 report scenarios have real screenshots/logs and PASS; (3) CSAT 1/5 and NPS 0/10 boundaries are accepted on distinct CLOSED, unsurveyed tickets; (4) invalid values return 400, duplicate surveys return 409, and cross-user survey access returns 404; (5) all three containers become healthy after a clean-volume build, and a second start does not duplicate seeded rows; (6) all three documented bugs are closed with separate reachable commits and no open Critical bug. Any unverified scenario remains PENDING in the report.

**Environment, data and cleanup.** Docker Desktop with Compose v2, Node.js 22 Alpine (container), PostgreSQL 17 Alpine, React/Vite frontend. The normal stack exposes API 3000 and frontend 5173. A separate Compose project using `compose.clean-test.yaml` exposes API 3002 and frontend 5175; it has its own PostgreSQL volume. Schema and seed scripts are mounted into `/docker-entrypoint-initdb.d/` and run only for an empty volume. Use only the separate test project for destructive operations; `docker compose -p smartcrm_bt3_clean -f compose.yaml -f compose.clean-test.yaml down -v` destroys **only that test project's data**. Do not use `docker system prune` or `down -v` on the primary project if it contains important data.

**Traceability.** CLOSED-only survey: TC08; one survey per ticket: TC07; CSAT/NPS ranges: TC04-TC06; authentication: TC09; survey ownership: TC11; repeatable deployment: TC10; regression fixes: BUG-01/02/03 unit tests. Evidence resides in `docs/screenshots/` and must match the final test results.
